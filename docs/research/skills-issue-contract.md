# What the Engineering skills expect from an issue and from docs/agents

Resolves ticket #2 of map #1. Source: mattpocock-skills 1.3.1, skill texts under
`~/.claude/plugins/cache/mattpocock/mattpocock-skills/1.3.1/skills/engineering/`
(paths below are relative to that directory). Everything here is read directly from those
files; items marked **[unverified]** are inferences, not quotes.

## Headline findings

1. Only **triage** has a rich, mandatory issue contract: exactly one category label + one
   state label, and an `## Agent Brief` comment as "the contract". Everything else is looser.
2. `implement`, `tdd`, `code-review` read **no labels at all**. They read the ticket body
   (implement), `GLOSSARY.md`/ADRs (tdd), and commit-message issue references (code-review).
3. `to-tickets` and `to-spec` apply `ready-for-agent` **without** an Agent Brief comment. So a
   `ready-for-agent` issue has two legal shapes: (a) triage-made, brief in a comment; (b)
   to-tickets-made, `## What to build` + `## Acceptance criteria` in the body.
4. **Wayfinder tickets are the opposite**: only `wayfinder:*` labels, "never a triage label like
   `ready-for-agent`" (`wayfinder/SKILL.md`). A Goal agent's issues must pick one world.
5. The skills read `docs/agents/*.md` only indirectly: the repo's `CLAUDE.md` has an
   `## Agent skills` block pointing at them, and skill texts say "the issue tracker ... should
   have been provided to you" (`setup-matt-pocock-skills/SKILL.md` lines 67-102).
   No skill text names a `docs/agents/` path itself except setup. **[unverified]** whether
   skills re-read the files or rely on the pointer in CLAUDE.md being loaded as context.
6. The wayfinder `## Notes` block of the map is the only per-effort config channel.

## The `ready-for-agent` issue shapes a Goal agent can produce

Both are accepted by `implement`, `implement-spec`, `code-review` because those do not parse
labels or brief structure; they just need the body to carry the intent.

**Shape A, triage-style (`triage/AGENT-BRIEF.md`):** an issue plus an `## Agent Brief` comment
with fields `Category`, `Summary`, `Current behavior`, `Desired behavior`, `Key interfaces`,
`Acceptance criteria` (checkboxes), `Out of scope`. "The original body and discussion are
context: the agent brief is the contract." Rules: no file paths or line numbers ("they go
stale"), behavioral not procedural, testable criteria, explicit scope boundaries. Needs
exactly one category + `ready-for-agent`.

**Shape B, to-tickets-style (`to-tickets/SKILL.md`):** `## Parent`, `## What to build`,
`## Acceptance criteria`, `## Blocked by`; sub-issue + native blocked_by edges;
`ready-for-agent`. Same no-paths rule: "avoid specific file paths or code snippets".

Minimum common core a Goal agent issue must satisfy to work with every skill:
- title and body in the project's `GLOSSARY.md` vocabulary (to-spec, to-tickets, triage,
  tdd, domain.md all demand it);
- testable acceptance criteria as checkboxes;
- explicit out-of-scope;
- exactly one of `bug`/`enhancement` and one state label (if triage must be able to process it);
- parent as native sub-issue, blockers as native `blocked_by` edges (to-tickets, wayfinder,
  implement-spec frontier);
- no file paths/line numbers;
- commits and PRs reference the issue (`Closes #n`): the only link code-review follows.

## docs/agents contract

- `issue-tracker.md`: command recipes (create/read/list/comment/label/close/sub-issue),
  PR-as-request-surface flag (default `no`), "publish to the issue tracker" = create an issue,
  "Wayfinding operations". Consumers: all skills that say "tracker should have been provided".
- `triage-labels.md`: maps five canonical roles to actual strings. Only `triage` (and
  to-spec/to-tickets when they say "apply `ready-for-agent`") use it. The `bug`/`enhancement`
  category labels are **not** in this file; `triage/SKILL.md` says label strings "may differ"
  but the mapping file only covers the five state roles. Gap: category label names are
  unconfigured.
- `domain.md`: read `GLOSSARY.md` (or `GLOSSARY-MAP.md`) and `docs/adr/`; "If any of these files
  don't exist, proceed silently"; use glossary terms; "Flag ADR conflicts" explicitly.
- Wiring: `CLAUDE.md` (else `AGENTS.md`) `## Agent skills` block with one-line summary + path
  per file; setup "Never create `AGENTS.md` when `CLAUDE.md` already exists" and edits the
  block in place (`setup-matt-pocock-skills/SKILL.md`). A Goal agent must not add a competing
  block or a second source of labels.
- Observed in this repo: `docs/agents/` has the three files; no `GLOSSARY.md` is committed in
  the ticket's worktree base at the time of research **[unverified for the main checkout]**.

## Conflicts and risks for a Goal agent

1. **Label worlds.** `wayfinder:*` (planning decisions) vs triage labels (implementation
   work). A Goal agent filing work issues must use triage labels; filing decisions must use
   `wayfinder:*`; never mix (`wayfinder/SKILL.md`).
2. **Triage exactly-one rules.** An issue labelled by an agent with two state labels makes
   triage "flag it and ask the maintainer before doing anything else". An unlabeled issue
   lands in triage's "Unlabeled" bucket, so a Goal agent's issue is triaged unless it
   pre-applies `needs-triage` or `ready-for-agent`.
3. **Disclaimer.** Triage requires every comment it posts to start with `> *This was generated
   by AI during triage.*`; a Goal agent's own comments are not covered, so distinguish them.
4. **Closing.** Nothing but triage (`wontfix`), wayfinder (resolution) and PR keywords closes
   issues. `implement` does not. A Goal agent that closes issues on its own would bypass
   all of these.
5. **Parent protection.** to-tickets "Do NOT close or modify any parent issue"; wayfinder
   edits the map (Decisions-so-far). A Goal agent must not edit parents that these skills own.
6. **Out-of-scope store.** `.out-of-scope/` is read by triage for enhancement rejections; a
   Goal agent's "out of scope" notes should reuse it rather than invent a parallel file.
7. **Autonomy flags.** `triage`, `implement`, `implement-spec`, `to-spec`, `to-tickets`,
   `wayfinder` carry `disable-model-invocation: true`, so a Goal agent cannot call them
   itself (consistent with map #1's out-of-scope item). `tdd` and `code-review` do not.
8. **HITL vs AFK.** `ready-for-agent` = "ready for an AFK agent"; judgment calls belong in
   `ready-for-human` ("note why it can't be delegated").
